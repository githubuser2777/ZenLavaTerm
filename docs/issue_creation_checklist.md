# Issue Creation Checklist

Use this checklist before submitting any GitHub issue in LavaTerm.

1. Define the problem clearly (what is broken, expected vs actual behavior).
2. Confirm it is reproducible (steps, environment, frequency).
3. Check existing issues to avoid duplicates.
4. Choose the correct issue type/template (bug, feature, task, question).
5. Write a clear title (short and specific).
6. Add a detailed description:
   - Context
   - Current behavior
   - Expected behavior
   - Why it matters
7. Provide exact reproduction steps.
8. Include environment details (OS, app version, branch/commit, runtime).
9. Attach evidence (logs, screenshots, stack traces, sample input/output).
10. Add scope and impact (who is affected, severity, blockers).
11. Suggest acceptance criteria (what must be true to close the issue).
12. Add labels, priority, and milestone.
13. Assign owner (if known) or request triage.
14. Link related PRs/issues/docs.
15. Review for clarity/completeness, then submit.
